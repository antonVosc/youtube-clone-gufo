# Промпты и результаты

Полные исходные диалоги — в `ai-dialogs/` (файлы сессий инструмента, не пересказы; см. `ai-dialogs/README.md`).
Ниже — примеры отдельных промптов проекта и кода, который они породили. Приемы: спецификация + критерии приемки вместо «сделай X»; инварианты формулируются заранее и тут же превращаются в тесты; один модуль на сессию; результат проверяется запуском, а не чтением.

## 1. Схема БД → `backend/app/models.py`, `alembic/versions/0001_initial_schema.py`

**Промпт:** «Спроектируй модели SQLAlchemy 2 для YouTube-клона: пользователи с ролями, канал 1:1, видео со статусом обработки, видимостью и флагом скрытия модератором, шаринг приватных видео, лайки ±1, комментарии с ответами, подписки, плейлисты, жалобы. Критерии: составные PK для связей (идемпотентность в БД), CHECK и UNIQUE в БД, а не только в коде; индексы под ленту и FTS по названию; refresh-токены хранить хэшем. Миграцию получить через autogenerate и проверить upgrade/downgrade/`alembic check`.»
**Результат:** 12 таблиц; на проверке выявлено, что `autogenerate` не умеет рендерить функциональный индекс с `regconfig` → индекс описан через `text("to_tsvector('simple', title)")`.

## 2. Права на видео → `app/deps.py::can_view_video`

**Промпт:** «Реализуй единую функцию доступа к видео. Правила: владелец/модератор/админ видят все; остальные — только ready и не скрытое; public/unlisted — всем, private — только по `video_shares`. Отсутствие прав = 404. Сначала напиши тесты `test_access.py` по матрице (аноним, чужой, друг, владелец, модератор) × (public, unlisted, private, hidden, processing) × (метаданные, комментарии, лайк, жалоба, медиа), потом код.»

```python
if video.is_hidden or video.status != VideoStatus.ready:
    return False
if video.visibility in (Visibility.public, Visibility.unlisted):
    return True
```

## 3. Загрузка и раздача → `routers/videos.py`, `routers/media.py`, `nginx/nginx.conf`

**Промпт:** «Видео не должны идти через FastAPI. Загрузка — presigned multipart в S3; раздача HLS — через Nginx `auth_request`, чтобы права проверялись на каждом сегменте, а бакет оставался приватным. Опиши схему, затем реализуй; для `<video>`/`<img>`, которые не умеют Authorization, предложи cookie с ограниченным Path. Проверь живым прогоном через настоящий Nginx.»
**Что вскрыл прогон:** (1) в regex `location` фигурные скобки `{36}` нужно брать в кавычки; (2) `add_header` в `location` отменяет заголовки уровня `server` → вынесены в `snippets/` и подключаются `include`; (3) `kombu` без закрепления версий был несовместим с `redis-py` → версии закреплены.

## 4. Транскодинг → `app/transcode.py`

**Промпт:** «Воркер: скачать исходник из S3, ffprobe, HLS 360p всегда и 720p если исходник ≥720p, master.m3u8, превью, загрузка в `videos/<id>/hls/`, статус ready; любая ошибка → failed с причиной. Функция принимает транскодер и фабрику сессий параметрами, чтобы тесты подменяли ffmpeg; отдельно интеграционный тест с настоящим ffmpeg.»

## 5. Seed → `app/seed.py`

**Промпт:** «Seed должен быть идемпотентным и создавать настоящие видео: генерируй ролики ffmpeg (lavfi) и пропускай через тот же `process_video`, что и воркер. Добавь пользователей всех ролей, приватное видео с выданным доступом, unlisted, скрытое, лайки, комментарии с ответами, подписки, плейлист, открытые жалобы.»

## 6. Сквозная проверка → `backend/scripts/smoke.py`

**Промпт:** «Напиши скрипт, который на работающем стенде проходит регистрация → загрузка частей через presigned URL → ожидание ready → чтение master.m3u8, плейлиста и сегмента → проверка приватности (аноним получает 403/404) → лайк → комментарий → лента/поиск. Падает с понятным сообщением на первом провале. `deploy.sh` запускает его в конце.»
